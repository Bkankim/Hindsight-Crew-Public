# 공개판은 운영 리포에서 단방향으로 내보낸다

이 프로젝트는 운영판과 공개판 두 판으로 나뉘고, 판마다 목적이 다르다(#4, 2026-11-08 결정).
- 운영판: 운영자의 비공개 운영 리포(공개판에서는 볼 수 없다). 운영자 한 사람의 실제 기억 시스템 정본이다. 실제 뱅크·개인 정책(`policies/local/`)·운영 기록·개인 맥락 이슈를 담는다. 기준은 "운영자의 운영이 잘 돌아가는가"이고, 공개를 이유로 운영 동작을 바꾸지 않는다.
- 공개판: 운영판에서 단방향으로 내보낸 새 공개 리포. 누구나 이 기억 시스템의 운영 방식을 보고 자기 정책을 설계할 수 있는 참고 구현이다. 코드·규칙 강제·공용 정책과 개인 뱅크 템플릿·태그 어휘·retain 형식·검증 절차·ADR·실험 보고서·작업 이력을 담고, 실제 뱅크·정책·기억 원문·개인 이름·이슈·PR은 뺀다. 독자는 처음 보는 개발자다.
  **대체됨(2026-11-10)**: 작업 이력은 담지 않는다.
  공개판은 운영판 HEAD 트리의 단일 커밋 스냅샷이고, 운영판 작업 이력은 비공개다(아래 "2026-11-10 개정").

두 판의 목적은 2026-11-09 개정했다(운영자 결정: 공개판 관리와 첫 공개·force push를 에이전트에게 위임).
공개판 관리 주체는 에이전트다. 내보내기 시점, 이름 표, 유출 관문, 문서 품질, 외부 기여 반영, 첫 공개와 force push까지 맡고, 결과는 운영자에게 보고한다.
운영판을 그대로 공개하지 않고, 운영판은 비공개 정본으로 두고 공개판을 새 리포로 만들어 단방향으로 내보낸다.
운영 이슈와 기록에는 사적인 생활 맥락이 계속 들어가므로, 코드와 운영 기록이 한 리포에 사는 지금 구조를 유지한 채 공개 경계만 내보내기 단계에서 관리하는 편이 가장 적게 바꾼다.
공개판은 커밋 이력을 유지하고(작업 흔적이 포트폴리오 증거다), 코드·테스트·하네스·공용 정책·ADR과 코드가 판정 근거로 가리키는 실험 보고서(`artifacts/arch-v2/`)를 담는다.
운영 기록(전환·롤백 기록, 검증 출력)과 개인 정책이 든 옛 테스트 고정 데이터 경로는 이력 전체에서 뺀다.
**대체됨(2026-11-10)**: 커밋 이력 유지는 단일 커밋 스냅샷으로 바뀌었다.
담는 경로와 빼는 경로의 경계는 그대로이고, 스냅샷 트리에 같은 경계를 쓴다.

공개판에 남는 경로의 개인 흔적은 HEAD와 과거 이력을 다르게 다룬다(하이브리드, 2026-11-09 개정).
- HEAD: 운영판에서 정식 커밋으로 고친다. 개인 정책 사본이던 테스트 고정 데이터는 같은 구조의 데모 고정 데이터(가상 뱅크·프로젝트 이름)로 바꾸고 테스트도 함께 고친다. 공개판 HEAD의 정합은 운영판의 테스트가 보장한다.
- 과거 이력: 테스트 통과 의무가 없으므로 유출 차단만 한다. 내보내기 때 치환 표를 이력 일부 경로(tests·docs·fixtures, 재태깅 표, 분리 전 공용 정책 파일)의 blob과 커밋 메시지에 적용한다. 식별 패턴이 든 표는 리포 밖 로컬 파일로 둔다.
- 검사: 치환 뒤 내보낸 이력 전체 blob을 경로와 무관하게 훑는 독립 유출 검사와, 이력에 남은 개인 이름이 치환 표에서 빠지지 않았는지 보는 표 누락 검사를 둔다.
- 코드 식별자와 겹치는 일반 단어는 치환하지 않는다. 프로젝트 자기 이름(hindsight-crew)도 그대로 둔다.
- 운영자의 실제 뱅크와 정책은 공개하지 않는다. 사용자는 공용 정책과 개인 뱅크 템플릿으로 자기 정책을 설계한다.

**대체됨(2026-11-10)**: 하이브리드 중 과거 이력 쪽(이력 일부 경로 치환, 과거 이력 대상의 독립 유출·표 누락 검사)은 도구가 그대로 돌지만,
공개판에 과거 이력이 없어 이력 치환과 그 검사의 적용 대상이 스냅샷 커밋 하나뿐이다.
HEAD 쪽(운영판 정식 커밋으로 고치고 운영판 테스트로 정합을 보장)은 그대로다.

내보내기는 같은 규칙으로 다시 만들었을 때 기존 공개 HEAD가 새 HEAD의 조상이어야 한다.
규칙을 바꿔 이력이 다시 쓰이면 공개판 force push가 된다.
force push와 첫 공개는 공개판 관리 주체(에이전트)가 관문 통과 뒤 실행하고 운영자에게 보고한다.
관문은 기계적이다: 독립 유출 0, 후보 안 전체 pytest 실패 0, 같은 입력 같은 sha, gitleaks 0.
이 관문에는 아래 개정으로 독립 LLM 리뷰 관문이 더해졌다.
**대체됨(2026-11-10)**: 조상 규칙과 fast-forward는 쓰지 않는다.
매 공개는 공개 리포 main을 새 스냅샷으로 갈아 끼운다(force push 또는 삭제·재생성).
관문 통과 뒤 공개판 관리 주체가 실행하고 운영자에게 보고하는 것과 기계 관문 4개는 그대로다.

공개 범위와 관문을 2026-11-09 다시 개정했다(첫 공개 직후 개정).
개정 사유: 첫 공개 직후 독립 리뷰가 기계 관문 4개를 모두 통과한 공개판에서 사적 맥락을 찾아,
공개 리포를 비공개로 되돌렸다.
이름 표·금칙 패턴·gitleaks는 정해 둔 꼴만 보므로,
이름 없이 맥락을 담은 자유 문장과 디렉터리째 담긴 새 운영 문서를 놓쳤다.
- 공개 범위: 공개용으로 쓴 것만 이력째 싣는다.
  `docs/`와 `scripts/`는 디렉터리째 담지 않고 공개용 파일을 하나씩 적고,
  운영 런북·계획·전환 창·리허설 기록·운영 뱅크 분석·운영자 표는 운영판에 그대로 두고 공개판 이력 전체에서 뺀다.
  공개 문서가 기대던 절차는 공개용 문서로 일반화해 옮긴다.
- 독립 LLM 리뷰 관문: 매 내보내기마다 기계 관문 4개에 더해 독립 LLM 리뷰어 2명의 리뷰를 통과해야 한다.
  두 리뷰어는 서로 다른 모델이고 서로의 결과를 보지 않는다.
  범위는 직전 공개 이후 바뀐 blob·경로·커밋 메시지이고,
  첫 공개와 force push면 공개판 전체다.
  **대체됨(2026-11-10)**: 범위는 매 공개 공개판 전체(스냅샷 트리와 커밋 메시지)다.
  통과 조건은 두 리뷰 모두 차단·높음 등급 사적 정보 0건이다.
  지적은 값을 가린 꼴과 위치로 리포 밖에 기록하고,
  해결한 뒤 같은 범위를 다시 리뷰한다.
  실행 주체는 공개판 관리 주체(에이전트)다.
- 기계 관문 4개(독립 유출 0, 후보 안 전체 pytest 실패 0, 같은 입력 같은 sha, gitleaks 0)는 그대로 둔다.
  리뷰 관문은 기계 관문을 대신하지 않고 기계 관문이 보지 못하는 자유 문장 맥락을 덮는다.

## 2026-11-10 개정: 공개판은 단일 커밋 스냅샷이다

결정(공개판 관리 주체, 2026-11-10, 운영자 지시): 공개판은 이력 없는 단일 커밋 스냅샷으로 낸다.
사유: 매 공개마다 과거 이력을 걸러 내는 비용이 든다.
다음 갱신도 그때의 운영판 HEAD 스냅샷만 올린다.
운영판 동작과 내보내기 도구 코드는 바꾸지 않는다.

관문 방식:
- 운영 리포의 별도 클론에서 원본 HEAD 트리로 부모 없는 고아 커밋 하나를 만든다(`git commit-tree`).
  작성자·커미터 이름·주소·날짜는 원본 HEAD 커밋 값을 그대로 쓰므로,
  같은 입력이면 같은 sha가 나온다.
- 그 커밋을 `--source-ref`·`--split-rev`로 주고 내보내기 도구를 그대로 돌린다(`--prev-public` 없음).
  도구판은 원본 HEAD의 `scripts/public-export/`다.
- 도구의 기계 검사 전부(주소 집합, 독립 유출, private-ipv4, 표 누락, 제외 경로, gitleaks, Exported-From, 구조 치환)가 HEAD 트리 기준 관문이 된다.
- 후보 안 전체 pytest와 독립 LLM 리뷰 2명은 그대로 둔다.
  리뷰 범위는 매 공개 공개판 전체다.
- 명령 절차는 `docs/public-export.md` "사용법"이다.

유지와 대체:
- 유지: 같은 입력 같은 sha. dry-run 2회의 공개 HEAD sha를 비교한다.
- 유지(보강): 도구가 붙이는 `Exported-From`은 고아 커밋 sha다.
  그래서 고아 커밋 메시지에 원본 운영 HEAD sha 한 줄 `Source-HEAD: <sha>`를 넣는다.
- 유지(방식 변경): `export/NNN` 태그.
  `--apply`는 `--source-ref` 커밋(고아 커밋)에 태그를 달기 때문에 쓰지 않는다.
  공개판 관리 주체가 원본 운영 HEAD sha에 주석 태그(본문: 스냅샷 sha, 공개 HEAD sha)를 직접 만들어 origin에 push한다.
- 대체: 조상 검사와 fast-forward 근거.
  매 공개는 공개 리포 main 갈아 끼우기다(force push 또는 삭제·재생성).
- 유지(근거 변경): 공개 리포 main 브랜치 보호(외부 PR 머지 차단, 소유자 force push 허용).
  근거는 조상 검사가 아니라 "공개판은 내보내기로만 바뀐다"다.
- 대체: 과거 이력 치환과 과거 이력 대상 검사(하이브리드의 과거 이력 쪽), 증분 리뷰 범위.
- 커밋 이력에 기대는 도구는 스냅샷 공개판에서 기준 커밋을 찾지 못한다.
  `bench/prune_effect.py`는 `Exported-From` 기준 커밋을 못 찾아 오류로 멈추고,
  그 테스트(`tests/test_bench_prune_effect.py`)는 기준을 못 찾으면 건너뛴다.
  `bench/README.md`의 `git show <sha>^` 안내도 공개판에서는 따라 할 수 없다.
  `bench/` 파일 자체는 이 개정에서 고치지 않는다.

## Considered Options

- 운영판을 그대로 공개: 이슈·PR·PR ref가 함께 공개되고, 스크럽해도 PR ref에 남는다.
- 기계 관문만 유지하고 금칙 패턴을 늘림(2026-11-09 기각): 금칙 패턴은 어순·동의어에 약하고,
  패턴을 늘릴수록 숨기려는 맥락의 해독표가 된다.
  자유 문장의 사적 맥락은 정해 둔 꼴로 다 잡을 수 없어 패턴을 늘리는 대신 독립 리뷰를 관문에 넣었다.
- 공개판을 코드 정본으로 옮기고 운영 기록은 별도 비공개 리포로 분리(B1): 가능하지만 지금 한 리포에 섞인 코드·운영 기록·이슈를 두 리포로 쪼개는 이전 작업이 크다.
- 이력 없는 단일 커밋 스냅샷(C): 가장 깨끗하지만 몇 달의 작업 흔적을 잃는다.
  **2026-11-10 채택**: 매 공개마다 드는 과거 이력 걸러 내기 비용 때문에 채택했다(위 "2026-11-10 개정").
- 커밋 이력 유지(하이브리드, 2026-11-09 결정): **대체됨(2026-11-10)**.
  작업 흔적이 포트폴리오 증거라는 근거로 택했지만,
  매 공개마다 과거 이력을 걸러 내는 비용이 들어 스냅샷으로 바꿨다.
  운영판 작업 이력은 비공개 운영 리포에 남는다.
- 내보내기 시점 이름 치환만으로 HEAD까지 처리(2026-11-09 기각): 운영판을 고치지 않아 가장 작지만, filter-repo 실험과 독립 리뷰에서 깨졌다. 일반 단어 치환이 코드 식별자를 바꿔 SyntaxError가 났고, 대소문자·오타 입력을 다루는 테스트 10건이 실패했으며, 경계 정규식으로 좁히면 HEAD에 개인 이름이 90회 남았다. HEAD는 테스트 의무가 있으므로 운영판 정식 커밋으로 옮겼다.

## Consequences

- 공개판에 들어온 외부 기여는 운영판에서 같은 변경으로 다시 만들고 기여자를 `Co-authored-by`로 표기한 뒤 다음 내보내기로 싣는다. 공개 PR은 반영 커밋을 알리는 댓글과 함께 닫는다.
  **대체됨(2026-11-10)**: 운영판 커밋의 `Co-authored-by`는 스냅샷에 실리지 않는다.
  기여자는 고아 커밋 메시지의 `Source-HEAD` 문단에 `Co-authored-by:` 줄로 넣는다(같은 줄 목록이면 같은 sha).
  공개 PR은 반영한 공개판 스냅샷 sha(또는 `export/NNN`)를 알리는 댓글과 함께 닫는다.
- 공개 PR을 공개 리포에서 머지하면 공개 HEAD가 내보내기 결과의 조상이 아니게 되어 다음 내보내기의 조상 검사가 깨진다.
  그래서 공개 리포 main은 브랜치 보호로 머지를 막고,
  force push는 공개판 관리 주체만 한다.
  **대체됨(2026-11-10)**: 조상 검사가 없어졌다.
  브랜치 보호(외부 PR 머지 차단, 소유자 force push 허용)는 유지하고,
  근거는 "공개판은 내보내기로만 바뀐다"다.
- 공개 범위를 공개용으로 쓴 것만으로 좁혔으므로,
  새 문서·스크립트는 매니페스트 `include`에 적어야 공개판에 실린다.
  적지 않은 운영 문서는 공개판에 닿지 않는다.
