# 태그 정규화는 선언된 어휘로 칸을 해석한다 (조건부)

2026-07-27 정규화는 "기계적으로만 고치고 의미를 만들지 않는다"를 원칙으로 두고, prefix 없는 단어를 전부 `topic:`으로 보냈다. 그 결과 `gotcha`·`demo-dev` 같은 단어가 `topic:gotcha`·`topic:demo-dev`로 쌓였고, 대청소 뒤 문서 1,154건 중 112건이 project 범위에서 빠져 멘탈 모델에 잡히지 않았다(#35). 그래서 맨단어와 칸 오배정 태그는 선언된 kind·project 어휘에 있으면 그 칸으로 고친다. 어휘 소속은 옛 이름 alias를 적용한 뒤에 본다(`done`→`kind:done`→`kind:completion`). 단 project로 옮기는 교정은 **그 기억에 project 태그가 없고, 옮길 후보가 정확히 하나일 때만** 한다. 다른 project가 이미 있으면 교차 참조로 보고 topic에 둔다(예: 다른 프로젝트 기록에 사이트 얘기로 붙은 `topic:demo-dev`). 후보가 둘 이상이면 모두 topic에 두고 경고한다. 어느 project의 기억인지 기계적으로 가를 수 없고, 잘못 옮기면 다른 프로젝트의 멘탈 모델로 기억이 새기 때문이다. 같은 project가 이미 있으면 topic 쪽 중복만 뺀다. 이 해석은 어휘를 선언한 뱅크에만 적용한다.

## Considered Options

- 항상 교정: 가장 단순하지만 다른 프로젝트의 기억이 섞여 들어간다.
- 교정하지 않고 거부: 원칙은 지키지만, 고칠 수 있는 값을 호출자에게 다시 치게 해 7/27 원칙과 충돌한다.
