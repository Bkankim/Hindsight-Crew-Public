# 실험 판정 요약

recall 튜닝과 메모리 아키텍처 v2(arch-v2) 실험의 판정을 한 장에 모은다.
수치는 리포 안 보고서(`artifacts/arch-v2/*.md`)와 [`bench/README.md`](../bench/README.md)의 값을 그대로 옮겼다.
새로 잰 값은 없다.
버전 칸은 측정 시점 값이고, 현행 값으로 바꾸지 않는다.

## 먼저 알아 둘 것

- **운영자 도구다.** 하네스는 한 운영 환경의 실사용 기록(백업 복제본, 운영 사이드카 로그)을 입력으로 쓴다.
  외부에서 같은 숫자를 재현할 합성 예제는 아직 없다.
- **리랭커·배치 실험의 채택 기준은 Pareto 개선이다.** 속도·정확도·비용 세 축에서 나빠지는 것이 없고 하나 이상 좋아질 때만 채택한다.
  arch-v2 런은 런마다 미리 정한 조건으로 판정한다(예: 런 5·6의 벤치 G3는 토큰 +5%까지 허용).
  가를 수 없으면 **보류**이고, 판정 규칙을 사후에 풀어 보류를 채택으로 바꾸지 않는다.
  용어 정의는 [`CONTEXT.md`](../CONTEXT.md)에 있다.
- **dev / holdout:** dev 쿼리로 후보를 고르고, holdout 쿼리는 후보마다 한 번만 쓴다.
- **A/A 대조:** 같은 설정의 두 팔(base, ctrl)을 함께 재서 잡음폭을 낸다.
  대조가 흔들리면(`aa-too-noisy`) 그 run은 무효이고 판정은 보류다.
- **arch-v2 경로 이름:** (a) reflect 나열, (b) 지식 페이지, (c) recall 최신 상태, (d) recall 목록, d-llm(목록을 LLM이 읽어 열린 일을 고르는 경로).
  arch-v2가 겨눈 증상은 "이미 끝난 일이 열린 일로 나온다"다.
- **S3:** 게이트웨이가 recall 응답에 열린 항목 표를 붙이는 기능(`HC_ITEM_OPEN_TABLE`).
- **G3:** 벤치 비용 조건(토큰 +5% 이내, p95 비열화 없음).
- **"정답 출처를 본 값":** GitHub 근거로 상태를 정한 표를 GitHub로 채점한 수치는 실력 지표가 아니다.
  보고서가 그렇게 표시한 값은 이 문서에서도 같은 표시를 단다.

## 읽는 법

- 같은 실험이 여러 행이면 위에서 아래로 시간 순이다(B1: 첫 판정 -> 재판정 -> 카나리).
- 판정 단어는 보고서의 말을 그대로 썼다.
  리랭커·배치 절의 PASS·FAIL·INCONCLUSIVE·NO-CHANGE는 `bench/judge.py` 종료 코드(0·1·2·3)이고, ROLLBACK은 카나리 판정(`bench/canary.py`)이다.
  arch-v2 표의 "벤치 PASS/FAIL/INVALID"는 팔 비교기 `bench/arm_compare.py` 종료 코드(0·1·2)이고, 런 7 사전 연막의 rollback(exit 4)·pass는 연막 관문의 판정이다.
- "벤치"는 속도·비용 비교기, "회귀"는 끝난 일·열린 일 정답 세트 채점이다.
  벤치 PASS는 비용·속도가 나빠지지 않았다는 뜻이지 recall 품질이 좋아졌다는 뜻이 아니다.
