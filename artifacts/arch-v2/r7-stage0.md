## 1. 새 원래 증상 채점식

분모 = 출력한 열린 항목 전체(status open).
정답표 대응 없음, PR, 없는 번호, 번호(키) 없는 일도 분모에 넣는다.
미확인 항목을 정답으로 치거나 분모에서 빼지 않는다.

항목마다 판정 하나(open = 분자, finished, wrong, hold = 판정 보류, unconfirmed = 미확인(GitHub 없음)).

| 항목 | 판정 근거 | open | finished | wrong | hold / unconfirmed |
|---|---|---|---|---|---|
| 키 있음, GitHub 연결(평가 캐시 리포 200) | t 시점 GitHub 범주(`r7_eval.item_at`, 재오픈은 리포 단위 events) | 열린 이슈 | 닫힌 이슈(완료·미계획), 머지 PR, 머지 없이 닫힌 PR | 열린 PR, 없는 번호, t 뒤 생성 | 닫힌 적 있는데 이벤트 없음 |
| 키 있음, GitHub 없음(리포 404·조회 실패·캐시에 리포 없음, `PR #N` 처럼 리포가 아닌 이름 포함) | t 시점 열린 이슈로 확인할 수 없다 | - | - | - | 전부 unconfirmed(P_key 분모에만). 보조 열: 역할 저장소 t 시점 상태, 없으면 근거 규칙(열림/끝남/보류) |
| 키 없음(모양이 아닌 키, 리포 없는 `#N` 포함, `#N` 수는 따로 공개) | 근거 규칙 | 규칙 열림 | 규칙 끝남 | - | 근거 없음·신호 없음·근거가 t 뒤 |

- 근거 규칙: 항목 `evidence_ids` 기억(그 팔 recall 결과 행, t 이하) 중 항목 `quote` 를 담은 문장의 규칙 역할
  (`item_roles.sentence_role`, 열림 표지어 우선). quote 문장이 없으면 `kind:completion` 기억은 끝남.
  시각이 가장 늦은 열림·끝남 신호가 판정이다.
  LLM 판정은 인터페이스(`judge=`)만 있고 이 측정은 부르지 않았다(코디네이터 결정 1).
- 지표: P_all = open / 열린 항목, P_all_github = GitHub 열린 이슈 / 열린 항목, P_key = GitHub 로 t 시점 열린 이슈임이 확인된 항목 / 키 있는 항목 전부
  (GitHub 없는 키는 분모에만, rework #403-1), P_key_linked = 열린 이슈 / GitHub 연결 키 항목.
  GitHub 없는 키의 뱅크·근거 규칙 판정은 미확인 범주 안 보조 열로만 낸다.
  단계 A 통과 기준 "키 있는 항목 P" 는 P_key 다.
- 표 밖 끝남 키 유입: 열린 항목 중 키가 있고 t 시점 GitHub 끝남 범주이며, 그 팔 응답 표에 그 키의 `확인된 종결`·`종결(미계획)`
  줄이 없던 항목. 반복당 평균. 보조로 뱅크 기준(표 밖 + 저장소 끝남) 수도 낸다.
- 항목 분해 코드: `키 유무|표 줄 상태|표 밖이면 뱅크 상태|GitHub 범주`.
- 옛 채점과 다르게 세는 경우는 `tests/test_r7_endtoend.py` `test_old_symptom_score_counts_unmapped_differently` 와
  범주 행렬(24경우)이 단언으로 고정한다.
  수정 전 red(옛 `symptom_score` 에 새 기대값을 단언, 22경우 중 14실패)는 리포 밖 `r7-work/red-403.txt`,
  미확인 범주로 바꾼 기대값의 red(rework #403-1, 미연결 키 경우가 `open` != `unconfirmed` 로 실패)는 `r7-work/red-403-1.txt`.
- 반복과 응답: 팔당 저장 recall 응답이 1개면 모든 반복에 그 표를 쓰고, 반복 수와 같으면 반복마다 그 응답의 표를 쓰며,
  그 밖이면 멈춘다(런 6·단계 A 는 팔당 recall 1회 + 생성 K회).
