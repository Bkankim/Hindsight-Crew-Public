### 질의 인자 재구성과 표

- R5-A2 recall은 태그 없이 `{query: 지시문 + 줄바꿈 + 문안, query_timestamp, max_tokens}`로 보냈다.
  하네스는 저장 recall이 같은 계획(plan sha256)·같은 질의 순서·같은 기준 시각인지 확인한 뒤 같은 인자를 만든다(`query_args`, 테스트가 `save_recalls`가 보내는 인자와 같음을 고정).
- 질의마다 `gateway/item_open_table`의 `wants_table` -> `role_states`(기준 시각 = 질의 `query_timestamp`) -> `request_repos` -> `build_table`을 그대로 부른다.
  태그가 없어 범위는 뱅크 전체이고, 한 t의 모든 질의가 같은 표를 받으므로 같은 텍스트는 1회만 붙는다(t당 표 1개).
- d-llm 입력 = R5-A2 합집합 -> 시간여행 필터 -> 렌더 행 + 표 텍스트(recall 행 뒤).
  표가 없는 설정으로 base1 gen 6개를 다시 만들면 `prompt_text_sha256`이 6/6 같다(하네스 입력 조립이 R5-A2 기준선과 바이트 단위로 같다는 확인).
  `judge`는 모든 반복에서 gen 머리 손잡이로 입력을 다시 만들어 `prompt_text_sha256`을 대조했다(6반복 x t 6개 전부 일치).

### 지표

- P·R(/기준선 결과에 나온 대조 49쌍)·R_all(/80)은 #372 정의(`r5_metrics.pr_summary`).
- R_bank(S4) 분모 = 대조 80쌍 중 S4 저장소 역할로 기준 시각 이하 마지막 비참조 언급이 열림인 쌍 = **58**(끝남 21, 언급 없음 1).

- 추가 토큰(텍스트) = 표 텍스트 `cl100k_base` 토큰 / 그 t의 필터 뒤 d-llm 입력 토큰, t별 최대. payload = 표 객체(`{t, fmt, rows, truncated, text}`) 압축 JSON(`recall_prune._dumps`) 토큰 / 같은 분모(recall 응답 하나에 실리는 양).
- 노이즈: base1~5(R5-A2 출력 재판정). R_bank(S4) 노이즈 바닥 **9.8pp**(반복 짝 10개의 키 군집 재표집 |Δ| 95 백분위 최댓값, 씨앗 20261101, 2000회, 관측 최대 |Δ| 5.2pp). #374 분모 바닥 9.7pp(#374와 같음). 노이즈 바닥은 채택 관문이 아니다(direction-9).

## 4. 오답 사유 분해

- 새로 생긴 오답 쌍(`cands`가 사유 파일에 없는 쌍만 냄): **60쌍을 새로 판독**했다(C1 2, C2 0, C3 58, 키 17개).
