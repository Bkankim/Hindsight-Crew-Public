# R5-A2 지표 2단·노이즈 바닥·오라클 상한 - P·R, 검색 지표, d-llm K=3, o1·o2·o3 (issue #362, 상위 #360)

**오라클 관문: o1 50.0% / o2 33.3% -> 통과**

**o3(뱅크 상태 표): P 85.7%(24/28) / R 49.0%(24/49). o3+o1: P 100%(20/20) / R 40.8%(20/49).**

**기준선(d-llm, 5회): P 65.0~70.7% / R 53.1~59.2%. 목표는 P >= 95%, R >= 90%.**

**R_bank(뱅크가 열림으로 기억하는 대조만 분모): 엄격 판본은 분모 1쌍(80쌍 중 79쌍이 뱅크 규칙상 끝남)이라 판정 불가. 느슨한 판본 R_bank2(분모 27쌍): 기준선 55.6~59.3%, o3 63.0%, o3+o1 44.4%(5절).**

- 주 지표는 P(목록 정밀도)·R(열린 항목 회수율 = G2)이다(#362 범위 확장, 운영자 결정). G1은 보조다.
- 관문(#360 A4)은 G1 오답 감소율로 판정했다.
  첫 기준선 반복(base1) 대비이고, 분모는 base1 오답 12쌍이다.
  o1은 문턱 50%에 정확히 걸린 경계 판정이다.
  기준선 5회 각각을 기준으로 다시 재면 o1 50.0~66.7%, o2 26.7~35.7%, o3 71.4~80.0%, o3+o1 100%다(4절).
- 표·주석형 오라클은 P를 올리고 R을 깎는다.
  o3+o1의 R 감소(-18.4pp)는 키 군집 재표집 95% 구간이 0을 포함하지 않는다(4절).
- R 손실의 주원인은 검색 단계(대조 80쌍 중 31쌍이 recall 결과에 없음)와 라벨-뱅크 불일치다(5절).

| 지표(dev, D10 사본, S1·X1 꺼짐) | recall 경로(LLM 없음, dev t 15개, 5회) | d-llm 경로(K=3, 표본 t 6개, 기준선 5회) |
|---|---|---|
| **P**(열림으로 나온 라벨 쌍 중 실제 열림) | - | **65.0~70.7%**(26~29 / 39~44) |
| **R = G2**(기준선에 나온 대조 쌍 중 열림) | **12.5%**(9/72) | **53.1~59.2%**(26~29/49) |
| R_all(표본 t 대조 80쌍 전부 분모) | - | 32.5~36.2% |
| G1(보조, 끝난 일이 열림으로 나옴) | **8.5%**(22/260) | **4.7~5.9%**(12~15/256), invalid 0 |
| 노이즈 바닥(키 군집 재표집 \|Δ\| 95 백분위 최대) | G1 **0**, G2 **0**(5회가 완전히 같음) | P **11.5pp**, R **11.3pp**, R_all 7.2pp, G1 2.8pp |

- 키 없는 항목 기준선(d-llm만, t=10-28): 세트 D P 66.7%(2/3) / R 25.0%(2/8), 세트 C는 키 없는 대조가 없어 R·P 없음(끝난 일 0/12 열림)(6절).
- d-llm 지출 **$23.72**(상한 $35, 범위 확장 전 상한 $20). 호출 167회(7절).
- 사본 구간: `2026-11-01 21:38:05 2026-11-01 23:19:32`(8절).

이 문서에는 수치·sha256·분류 코드만 쓴다.
질의·응답 원문, 기억 본문, 리포 이름+번호 목록, 뱅크 실명, 개인 경로는 쓰지 않는다(공개 전환 가드 #4).
도구는 `bench/r5_metrics.py`·`bench/r5_oracle.py`(규칙 정본은 모듈 머리 주석), 테스트는 `tests/test_r5_metrics.py`, 명령은 `bench/README.md` "런 5" 절의 "지표·노이즈 바닥·오라클" 하위 절이다.

## 1. 측정 설계

### 질의와 입력

- 라벨셋: R5-A1 `r5-a1-labelset.jsonl`(sha256 `1f80c39db905ead9aa8b026526397a630eaf1362c9055b8fe6c96e7a33f3098e`).
  dev 분할의 양성 449쌍·대조 156쌍만 쓴다.
  봉인(`split=sealed`)·미사용 쌍은 질의·계산하지 않았다.
  `plan`·`dllm`·`judge`는 dev 마지막 t(10-13) 뒤 ~ 라벨 상한(10-27)의 t를 거부한다.
- 질의(t마다): 런 4 요청 가족 8개(`r4-1-families.json`, sha256 `14e95ce8...`) + 그 t에 dev 양성·대조 쌍이 있는 프로젝트마다 상태 질의 1개.
  프로젝트 질의 문안은 리포 밖 `r5-a2-project-query.txt`(sha256 `1ed2456609143aeb3c93942056154e48e19d750cdb858574c4d04507ff6638a8`)다.
  고정 지시문은 런 4 `r4-1-instruction.txt`(sha256 `442e4ef7...`)의 기준 날짜를 t로 바꿔 앞에 붙였다.
  `query_timestamp` = t 23:59:59 KST, `max_tokens` = 16384.
  질의 계획 `r5-a2-plan.json` sha256 `ca9a9cfb1d14e68b9c8be2b922e30e35d60bcce8544ab2a06cbfaa0ffc0c6e5d`(dev t 15개 200질의 + 키 없는 t 10-28 요청 가족 8질의).
- 프로젝트별 상태 질의를 넣은 근거(#360 열린 결정): 요청 가족은 "남은 일" 목록 질의라 끝난 일 근거 행을 덜 부른다.
  라벨셋은 프로젝트 단위로 키를 잡으므로, 프로젝트마다 열림·끝남을 함께 묻는 질의 1개로 두 쪽 근거가 함께 결과에 오르게 했다.
- (키, t) 입력: t의 모든 질의 결과 합집합(질의 순 -> 순위 순, 기억 id 중복 제거) -> 시간여행 필터.
  필터는 `mentioned_at` > t 23:59:59.999999 KST 이거나 없는 행을 뺀다(관찰 포함).
  검색 지표와 d-llm 입력이 같은 필터 뒤 합집합을 쓴다.

### 지표 정의

- 행의 키 = `gateway/item_keys.py`의 `extract_keys`(본문 + 태그, 별칭 표 = 라벨셋과 같은 실험 표).
  완료 계열 = 라벨 쪽 `r5_labels.is_done_family`(태그만).
  지표 모듈은 게이트웨이 쪽 완료 판정(X1·S1)을 import하지 않는다(테스트 `test_metrics_module_does_not_import_gateway_completion_rules`).
- recall 경로 열림 = 낡은 열림 행(그 키를 말하는 완료 계열 아닌 행)이 있고, 완료 근거(완료 계열 행 또는 S1 구조 필드 `gateway_item_ledger`의 done 칸)가 없음.
  키가 결과에 없으면 absent(열림 아님).
  S1 주석은 구조 필드로만 인식한다(본문 주석 문안은 보지 않는다).
- G1_recall = 기준선 결과에 키가 나온 양성 쌍 중 열림.
  G2_recall = 기준선 결과에 나온 대조 쌍 중 처치 뒤에도 나오고 완료 표시가 없는 쌍.
  기준선끼리 비교(노이즈)는 첫 반복을 기준선으로 둔다.
- d-llm: 동결 기준선 프롬프트(`bench/prompts/d_llm_baseline.txt`, query_date = t), `claude-sonnet-5-5`, K=3, 입력 상한 200,000자.
  대응은 동결 `bench/d_llm_match.py`.
  작업 표 = 그 t의 dev 양성·대조 키(key = 정규 키 + 별칭 표기).
  쌍 상태는 open 반복이 과반(2/3)이면 open, open + invalid가 과반이면 invalid(별도 칸, 분모에 남음), 그 밖은 not_open이다.
  출력 실패·빈 목록 반복은 invalid다.
- **P** = open으로 나온 dev 라벨 쌍(양성·대조) 중 대조(실제 열림) 비율.
  라벨셋에 없는 작업을 말하는 열림 목록 항목은 P에 들지 않는다.
  그런 항목 수는 따로 셌다(기준선 반복마다 t당 열림 항목 9~22개 중 5~16개, 3절).
- **R** = 기준선 결과(필터 뒤)에 나온 대조 쌍 중 open(= G2_dllm).
  R_all은 표본 t의 대조 쌍 전부를 분모로 한다(검색 손실 포함).
- G1_dllm = 기준선 결과에 키가 나온 양성 쌍 중 open.
- 노이즈 바닥: 반복 짝(i<j)마다 키 단위 군집 재표집(같은 키의 여러 t를 한 군집으로 복원 추출, 씨앗 20261101, 2000회)으로 |Δ|의 95 백분위를 내고, 그 최댓값을 바닥으로 둔다.
  P는 (분자, 분모) 쌍 값으로 같은 재표집에 넣는다.

### d-llm 표본

- 표본 t = dev t 중 양성 쌍이 가장 많은 마지막 6개(09-28, 10-01, 10-04, 10-07, 10-10, 10-13).
  dev 양성 449쌍 중 436쌍, 대조 156쌍 중 80쌍이 이 t에 있다.
- 근거: t 하나·설정 하나의 K=3 비용이 첫 측정에서 약 $0.57(캐시 생성 포함)이었다.
  처음 상한 $20 안에 기준선·o1·o2·반복·키 없는 기준선을 넣으려면 t 6개가 상한이었다.
  범위 확장(상한 $35) 뒤에도 비교 가능성을 위해 같은 표본을 썼다.
  앞쪽 t(09-01~09-25)는 dev 양성이 0~4쌍이라 G1 표본 기여가 작다.

## 2. 검색 지표(recall 경로, LLM 없음)

recall 5회(`rep1`~`rep5`), dev t 15개.
5회의 필터 뒤 입력은 모든 t에서 기억 id 순서까지 같았다(recall이 결정적).
그래서 recall 경로 노이즈 바닥은 G1·G2 모두 0이다.
R5-C의 최소 효과 `max(노이즈 바닥 x2, 키 1개)`는 recall 경로에서 "키 1개" 쪽이 정한다.

| 항목 | 값 |
|---|---|
| dev 양성 쌍 / 결과에 나온 쌍(G1 분모) / absent | 449 / **260** / 189(42.1%) |
| 양성 쌍 상태(기준선) | 열림 22, 닫힘 238(그 키의 완료 계열 행이 결과에 있음), absent 189 |
| **G1_recall** | **8.5%**(22/260), 5회 같음 |
| dev 대조 쌍 / 결과에 나온 쌍(G2 분모) / absent | 156 / **72** / 84(53.8%) |
| 대조 쌍 상태(기준선) | 열림 9, 닫힘 63, absent 84 |
| **G2_recall** | **12.5%**(9/72), 5회 같음 |
| 노이즈 바닥 G1 / G2 | 0 / 0(관측 최대 \|ΔG\| 0 / 0) |
| 결과에 S1 구조 필드가 달린 행 | 0(S1 꺼짐) |

  그래서 R5-C는 G2_recall을 기준선 대비 퇴행만 보는 가드로 쓰고, 절대값 목표는 d-llm 경로의 R로 판정하는 것이 맞다.

## 3. 종단 지표(d-llm 기준선)

기준선 5회 = recall `rep1`~`rep5` 입력(필터 뒤, 5회 같음) 각각에 K=3.
입력 행 113~157, 잘린 행 0(입력 104,661~134,562자).

| 반복 | P(대조 open / open 라벨 쌍) | R(open/49) | R_all(open/80) | G1(open/256) | invalid 쌍 | 비용 |
|---|---|---|---|---|---|---|
| base1 | 70.7%(29/41) | 59.2%(29) | 36.2% | 4.7%(12) | 0 | $3.413 |
| base2 | 69.2%(27/39) | 55.1%(27) | 33.8% | 4.7%(12) | 0 | $1.589 |
| base3 | 65.9%(29/44) | 59.2%(29) | 36.2% | 5.9%(15) | 0 | $1.498 |
| base4 | 65.1%(28/43) | 57.1%(28) | 35.0% | 5.9%(15) | 0 | $1.570 |
| base5 | 65.0%(26/40) | 53.1%(26) | 32.5% | 5.5%(14) | 0 | $1.547 |

- G1 분모 = 기준선 결과에 키가 나온 양성 쌍 256(표본 t 양성 436 중 absent 180 제외).
  R 분모 = 기준선 결과에 나온 대조 쌍 49(표본 t 대조 80 중 absent 31 제외).
- 출력 실패 반복 1회(base2 10-01, 재시도로 유효), 빈 목록 반복 0, invalid 쌍 0.
- 노이즈 바닥(기준선 5회 10짝): **P 11.5pp**(관측 최대 5.7pp), **R 11.3pp**(관측 최대 6.1pp), R_all 7.2pp(3.7pp), G1 2.8pp(1.2pp).
- 목록의 열림 항목 중 라벨셋 밖 작업을 가리키는 항목이 많다(t·반복당 열림 항목 9~22개 중 5~16개가 라벨 쌍에 대응하지 않음).
  이 항목들의 참·거짓은 이 자로 판정할 수 없어 P에 들지 않는다.
  P는 라벨 쌍 안의 정밀도다.
- 기준선 G1_dllm 평균 5.3%다.
  표본 안에서는 이미 G1 목표(<= 5%) 근처이고, 그 차이는 노이즈 바닥보다 작다.
  주 결손은 P(약 68%)와 R(약 57%)이다.

## 4. 오라클

같은 rep1 필터 뒤 입력을 고쳐 K=3을 다시 돌렸다(`bench/r5_oracle.py`).

- o1: 그 t의 dev 양성 키를 말하는 완료 계열 아닌 행 앞에 `[항목 상태: <키> 끝남 <날짜> 근거 <id>]` 주석을 붙였다.
  근거는 R5-A1 기억 메타(`r5-a1-meta.jsonl`, sha256 `b768775132b764abcdd05d61ef5722f457b633064659b4f22d826e562ffc0d7b`)의 그 키 최신 유효 완료 계열 기억(<= t)이다.
