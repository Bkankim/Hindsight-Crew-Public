# R7-4 운영 시점 연막 실행기 + 사전 연막 드라이런 (issue #408, 상위 #393)

운영 무변경 측정이다.
운영 게이트웨이에는 recall 읽기만, 운영 뱅크에는 나열 GET 만 보냈다.
운영 역할 저장소 원본은 읽기만 했다(복사 전후 sha256 같음).
판정은 상위 몫이고, 이 문서는 값과 기준 대비만 적는다.
원문(키·질의·응답·기억 본문·d-llm 출력)은 리포 밖 `r7-4-work/`(0700/0600)에만 있다.

## 첫머리: 기준 대비

| 기준(보고만) | 값 | 기준 대비 |
|---|---|---|
| 거짓 열림 0 | **2** (표 안 2, 표 밖 0, 모두 없는 번호) | 미충족 |
| 확인된 종결·종결(미계획) 오류 0 | 원래 증상 표 0·0, 프로젝트 표 0·0 | 충족 |
| 열림 후보 정밀도 >= 95% | 원래 증상 표 100%(18/18), 프로젝트 표 100%(10/10) | 충족 |

실행기 관문 판정은 `rollback`(exit 4)이다.
거짓 열림 2건은 반복 3개 중 1개(반복 2)에서 나왔다.
두 키 모두 그 리포의 t0 최대 번호보다 큰 번호다.
표에서는 `미확인·충돌`(no-number) 줄이었고, 소비자는 두 항목에 `unverified` true 를 달고 열린 목록에 올렸다.

## 1. 실행기 정의 (목표 1)

`bench/r7_endtoend.py`, 명령과 인자는 `bench/README.md` "운영 시점 연막 실행기" 절.

- t0 일치 검사: recall 요청 시각(저장 recall `query_timestamp`), 소비자 프롬프트 기준일(생성 머리 `t` = t0 의 KST 날짜.
  프롬프트를 다시 조립해 `prompt_text_sha256`·`table_sha256` 을 대조), 채점 t0(`--t0`, 생성 머리 `t0`).
  어긋나면 실패 코드 `t0-request`·`t0-prompt`·`t0-score`.
- `score --t0`: 기본값(10-28 `SYMPTOM_TS`)이면 생성·recall 파일 날짜와 요약이 이전과 같다.
  단계 A 저장 생성물로 다시 돌린 요약 sha256 `29fb9ab997ac3e1e...`, 상세 `d0f3d26243970dee...` 로 원래 파일과 바이트가 같다
  (`--t0` 생략, `--t0 2026-10-28T14:59:59Z` 둘 다).
- 평가 캐시: `smoke` 가 t0 에 GitHub 에서 새로 받는다(GET). R7-0 캐시를 받는 인자가 없다.
  같은 t0 로 받은 캐시만 다시 읽고, 리포 `fetched_at` 이 t0 보다 이르면 멈춘다.
- 관문(롤백): 거짓 열림 = 키 있는 열린 항목 중 t0 시점 GitHub 끝남(종결·미계획·머지·닫힌 PR), 없는 번호(t0 뒤 생성 포함),
  그 응답 표의 반증 줄(`확인된 종결`·`종결(미계획)`, GitHub 는 끝나지 않음). 표 안팎 합계. 1건 이상이면 exit 4.
- 참고: P_key, P_all, 키 없는 항목 수와 끝남 수, 열린 PR 유래 항목 수, `residual` 로 낸 t0 끝남 키 수.
- 실패(exit 1): t0 불일치, 표 미부착, 칸 누락, 빈 분모, 유효 생성 부족(기본 K 전부), recall·프롬프트·표 sha256 불일치.
- 테스트: `tests/test_r7_endtoend.py` #408 절(parametrize 행렬). 수정 전 red 22 failed, 17 errors(리포 밖 `red-408.txt`).
