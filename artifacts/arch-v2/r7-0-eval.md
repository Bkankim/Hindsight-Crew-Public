## 정의

- 표: 역할 저장소를 게이트웨이 공개 함수(`read_store`·`role_states`·`build_table`)로 읽어 만든 기준일 t 의 뱅크 전체 열린 키
  표(손잡이 `scope` all, `recent_done_days` 0, `max_rows` 1000, 나머지 기본값). 표 키 = `rows` 중 열림 키 전부. 잘림은 모든
  기준일 0. hindsight-crew 꼴 = 같은 표에서 리포가 hindsight-crew 인 키.
- t: 운영 = 사본 복사 시각. dev = R5-A2 계획의 `query_timestamp`(그날 23:59:59 KST). 봉인 구간 t 와 봉인 저장물은 쓰지 않는다
  (하네스가 exit 2 로 거부).
- 범주(t 시점): 열림(open_issue) / 닫힘c(closed_completed) / 닫힘np(closed_not_planned, duplicate 포함) / PR 열림·머지·닫힘 /
  없는 번호 / 리포 없음(소유자 해석 뒤 404) / t뒤생성(not_yet) / 이력없음(reopened_unknown, 이번 측정 0). 이슈 레코드에
  `pull_request` 가 있으면 PR 이고 PR 은 언제나 열림이 아니다. 재오픈·재닫힘은 리포 단위 issue events 의 closed·reopened 로
  t 시점 상태를 정한다.
- 표 정밀도 = 열림 / 표 키 전체. 회수율 = t 시점 실제 열린 이슈(PR 제외, 표에 오른 리포 + 별칭 표 정규 리포 중 존재하는 리포)
  중 표에 오른 것. 보조 회수율 = 분모를 저장소(t 이하 valid 기억, ref 포함)에 키가 있는 열린 이슈로 좁힌 값.
- 원인(표 오류 키 = 열림이 아닌 키, 여럿이면 모두 센다, 괄호는 주 원인 수, 주 원인 순서 5 > 1 > 4 > 2 > 3 > 데이터층 > 기타):
  - 5 PR: 상태를 정한 open 언급 기억의 그 키 문장이 모두 `PR #n`·`pull #n` 표기에서만 키를 낸다.
  - 1 범위: 그 문장이 모두 범위 표기(`#a~#b`·`#a-#b`·`#a..#b`, 리포 접두 포함) 양 끝에서만 키를 낸다(양끝), 또는 결정 시각 이후
    t 이하 기억에 끝냄 역할 양 끝을 가진 범위(20개 이하)가 그 번호를 안에 품는다(안쪽).
  - 4 번호만: 그 문장이 모두 번호만 규칙(`#n`, project 태그)으로만 키를 내고, 고정 문맥 낱말(#395 와 같은 목록)이 있거나 번호가
    그 리포 명시 표기(`<repo>#n`·`owner/repo#n`·`item:` 태그, t 이하 valid 기억) 최대 번호를 넘는다(상한 초과).
  - 2 동점: 상태를 정한 시각에 다른 기억의 done 언급이 같은 `mentioned_at` 으로 있다(기억 사이). 기억 안 동점은 저장소가 기억 단위
    병합 역할만 담아 셀 수 없다.
  - 3 끝냄 뒤 open: 상태를 정한 open 언급보다 이른 done 언급이 있다.
  - 데이터층: GitHub 에서 끝난 범주(닫힘·PR 머지·PR 닫힘)이고 끝난 시각 이후 t 이하에 그 키의 done 언급이 없다.
  - 기타: 위 어느 것도 아님.
  본문: dev = 런 5 본문 덤프 + 기억 메타, 운영 = 운영 뱅크 `memories/list` GET 1회 저장본(`ops-listing`). t 뒤 `mentioned_at`
  기억은 쓰지 않는다. 결정 기억 본문이 없어 1·4·5 를 못 가른 오류 키는 모든 기준일 0.

## 한계

- 원인 1·4·5 표지는 문장 단위 규칙 재현(키 추출 v1 `extract_keys` 에서 범위·PR 표기를 지우거나 번호만 규칙을 끄고 다시 뽑아
  비교)이다. R7-1 v2 규칙의 실제 효과는 R7-2 가 잰다. 원인 4 상한은 이 측정에서 본문으로 센 값이고 R7-1 meta 상한 표와 다를 수 있다.
- 원인 2 는 기억 사이 동점만 센다(저장소는 기억 단위 병합 역할만 담는다).
- 리포 없음: 소유자는 런 5 캐시가 해석한 값, 없으면 기본 소유자다. 다른 소유자의 리포를 가리키는 키도 여기로 들어간다.
- 회수율 분모의 리포 범위(별칭 표 정규 리포 98개 중 존재 42개)는 별칭 표가 정한다. 별칭 표 밖 리포의 열린 이슈는 분모에 없다.
- 이벤트는 리포 단위 `issues/events` 한 번으로 받았다(이슈마다 `issues/<n>/events` 대신). 닫힌 적 있는 표 키 이슈의 이벤트가
  빠지면 이슈 단위로 보충하는 경로가 있으나 이번 측정에서 보충 0건, 이력없음 0건이다. PR 머지 시각은 이슈 레코드의
  `pull_request.merged_at` 으로 얻어 `pulls` 목록 호출은 0회다.
- 운영 기억 나열은 복사 뒤 9분(04:02 KST)에 받았다. 복사 시각 뒤 `mentioned_at` 기억은 원인 판정에서 뺐다.
