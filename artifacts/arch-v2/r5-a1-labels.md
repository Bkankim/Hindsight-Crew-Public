## 3. 라벨 규칙과 t

- 끝남(t): `state_reason=completed`이고 `closed_at <= t` 끝 시각. 열림(t): `created_at <= t` 끝 시각이고 아직 열렸거나 `closed_at > t` 끝 시각.
- 제외 이슈: PR, 재오픈 이력(키로 쓰이는 닫힌 이슈마다 `issues/<n>/events`를 받아 `reopened` 확인, 지금 `state_reason=reopened`인 열린 이슈 포함), `not_planned`, 그 밖의 닫힘 사유(`closed_other`: `duplicate`·빈 값 등 completed·not_planned 밖 사유, **이번 데이터에서는 0건**). 제외 이슈는 모든 t 에서 라벨이 없다.
  - `closed_other` 근거(#360 정의의 확장, final-review #361-1 에서 유지로 판정): 끝남은 `state_reason=completed`만이므로 다른 사유로 닫힌 이슈는 닫힌 뒤 t 에서 끝남도 열림도 아니다. not_planned 와 같은 모양으로 이슈째 뺐다.
  - 재오픈 확인이 빠진 캐시(키로 쓰인 닫힌 이슈에 events 결과가 없음)로는 `build`가 exit 1 로 거부한다(final-review #361-1).
- 양성 = 끝남 + t 이전 완료 계열 기억. **데이터층 = 끝남 + t 이전 완료 계열 기억 없음**(#360 "없으면 데이터층(기억 없음)"). 데이터층 행은 하위 분류 `data_sub`를 갖는다: `no_completion`(그 키를 말하는 기억은 있지만 완료 계열이 없음) / `no_mention`(그 키를 말하는 기억도 없음). 데이터층은 G 지표 분모에 들어가지 않는다(보고용). 대조 = 열림 + t 이전에 그 키를 말하는 기억. 열렸는데 기억이 없으면 `control_no_memory`로 센다(라벨 아님).
  - 첫 커밋은 언급도 없는 끝남 쌍을 라벨 밖(`done_no_memory`)으로 뺐다. final-review #361-1 에서 스펙대로 데이터층 하위 분류로 바꿨다.
- t: 2026-09-01부터 3일 간격, 상한 = 마지막 `mentioned_at`의 KST 날짜 **2026-10-27**(D10 백업 시각과 같은 날). t 19개(09-01 ~ 10-25). 고유 양성 키 194(dev 108, 봉인 58 포함)가 60 이상이라 t 시작을 앞당기지 않았다(가장 이른 기억 07-24).

## 4. 분할과 봉인

- 봉인 구간 = 상한 직전 8일 [2026-10-20, 2026-10-27](이 안의 t 는 10-22·10-25). dev = 봉인 키가 아닌 키의 쌍 중 t <= 봉인 시작 - 5일 = **2026-10-15**(마지막 dev t 10-13). 간격 t(10-16·10-19)는 dev 에 넣지 않는다. fold = 키의 정규 repo.
- 봉인 키(#360 "봉인은 키로도 나눈다" 20:13 개정, rework #361-1): 봉인 구간에 쌍이 있는 키를 층으로 나눈다. 봉인 구간에 양성 쌍이 있으면 양성 층(두 층에 다 걸리는 키 포함), 아니면 대조 쌍이 있으면 대조 층. 층마다 키를 정렬해 씨앗 20261101(`random.Random`, 양성 층 다음 대조 층 순서로 같은 생성기)으로 섞고 앞 floor(n x 0.3 + 0.5)개(층이 비지 않으면 최소 1키)를 고른다. 봉인 구간에 데이터층 쌍만 있는 키는 층 밖이라 봉인 후보가 아니다. 데이터층 쌍도 키 분할을 따른다.
  - 층 크기: 양성 194키 -> 봉인 58키, 대조 22키 -> 봉인 7키. 봉인 키 **65**.
  - 봉인 테스트 = 봉인 키의 봉인 구간 쌍만(양성 116쌍, 대조 14쌍, 데이터층 0). 봉인 키의 다른 t 는 쓰지 않는다(미사용 칸).
- **dev 키 123 ∩ 봉인 키 65 = 0**(`build`가 겹치면 exit 1, 테스트 `test_sealed_keys_out_of_dev_and_pairs_only_in_window`). 같은 씨앗이면 입력 순서와 무관하게 같은 봉인 키가 나온다(`test_holdout_deterministic_by_seed`).
- 봉인 쌍의 recall·d-llm 결과는 만들지 않았고 열지 않았다.
- **개정 전 규칙의 수**: 봉인 키 = 처음 라벨된 t 가 봉인 구간에 드는 키로 두면 봉인 7키(양성 2키 4쌍, 데이터층 5키 10쌍, **대조 0**), dev 양성 645쌍(153키)·대조 213쌍(65키)이었다(라벨셋 sha256 `940714a867ebe0ea681246b7a11dbb591a1c9c25315d39ff5f40d4fc7348224d`, 커밋 `c0e9d53`).
- **개정 사유**: 개정 전 규칙으로는 봉인 대조가 0이라 R5-D 의 봉인 G2(열림 유지)를 잴 수 없고 봉인 G1 도 2키뿐이었다.

## 8. 알려진 한계(final-review #361-1 기록, 고치지 않음)
