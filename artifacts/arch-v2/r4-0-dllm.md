채점: 세트 C 정답표(sha256 `b9ecf188...6eb284`, `--expect-key-sha256`로 확인)의 id와 `item_keywords()` keyword만 쓴 작업 표(#349 "R4-0 재현 채점의 정답표 예외").

- `unverified` 비율: 67/108 = 0.62(항목 기준). open으로 대응된 작업 5개(K05, SC02, C02, SC04, SC05)는 5회 모두 `unverified=true` 항목으로 들었다. 열림율 계산에서는 open으로 셌다(#349).
- 항목별 열림율(id만, 0 아닌 것): 끝난 항목 K05 1.00. 대조군 C02 1.00, SC02 1.00, SC04 1.00, SC05 1.00, SC28 0.20(나머지 4회는 partial = residual). partial 범주 K01·K02·K16은 목록에 없음.

## 7. 제안(사전 등록 v4 1부 나머지 입력)

- **K = 7** (하한 5). 근거: 반복당 약 60~80초, 캐시 적중 뒤 반복당 약 $0.09~0.12, 입력당 첫 호출 캐시 생성 약 $0.3. 홀수라 과반이 명확하고, #349 순열 영분포가 floor(K/2)씩 두 묶음을 쓰므로 K=5(2 대 2)보다 K=7(3 대 3)이 묶음 분산이 작다. 비용은 입력 하나당 약 $0.9.
- **입력 상한 = 200,000자**(`--max-input-chars 200000`). 이 입력은 0.73 토큰/자(82,850자 -> 60,438 토큰)라 약 146,000 토큰이고 출력(최대 11,413 토큰) 여유를 둔다. 넘으면 뒤 행을 잘라 `truncated_rows`로 기록한다. 이번 입력 3종은 모두 상한 아래(잘림 0)다.
- **R4-1 recall `max_tokens` = 16384**. 근거: 16384 합집합(91행)이 6회 합집합(92행)과 거의 같고 4096 합집합은 36행이다(6절). 4096 입력에는 재현 항목 K05의 근거 행이 빠져 증상이 보이지 않았다(mt4096 과반 미달). 16384 단독 입력은 재현 기준을 충족했다.
