# 런 3 R3-2: 시험지 v2(세트 C)와 경로 (d), 영분포 (issue #341)

상위: #336. 도구 변경은 `bench/arch_v2_regression.py`(경로 (d) 등록과 질의 단계, `evidence --controls`, `select`), 사용법은 `bench/README.md` "경로 (d)와 시험지 v2 (런 3, issue #341)" 절.
이 문서에는 id·판정·해시·수치만 쓴다(정답표 항목 이름, 원래 증상 항목 이름, 질의·응답 원문, 기억 본문, 리포 이름, 뱅크 실명 없음, 공개 전환 가드 #4). 원문은 리포 밖 `~/.local/share/hindsight-bench/arch-v2/`(0700)에만 있다.

## 1. 선정 규칙 (사본 질의 전에 고정)

정답표(세트 A·B)와 진단 라벨은 선정 입력이 아니다. 세트 A·B 파일은 (i) 같은 일을 가리키는 후보를 원래 id 그대로 바이트 복사하는 것, (ii) 세 공유 값(`query_date`·`ignore_mentioned_at_from`·`query_instruction`)을 옮기는 것에만 읽는다.

### 1.1 층과 비율

- 끝난 항목은 두 층으로 나눈다. 키 있음 = 그 일 자체를 이슈 번호로 가리킬 수 있음, 키 없음 = 그렇지 않음. 키 유무는 출처로만 정한다(원래 증상 항목은 R3-0 항목표의 "키" 열, 닫힌 이슈 = 있음, 완료 기록 = 없음).
- **세트 C 끝난 항목의 키 있음 : 없음 = 1 : 1.** 두 층에서 아래 1.3을 통과한 수 중 작은 쪽 m 개씩을 후보 목록 순서(원래 증상 먼저, 그다음 표본 순서) 앞에서부터 남긴다. 넘친 쪽은 `excluded`(`stratum-quota`)로 남기고 채점하지 않는다.
- 원래 증상 끝난 항목(1.2 의 1번)은 선정 run 조건 없이 넣지만 이 1 : 1 층 수에 들어간다: 키 있음 3개, 키 없음 6개(R3-0 항목표 "키" 열).
- 대조군·partial 은 비율을 맞추지 않고 층별 수만 보고한다.

### 1.2 후보 출처(순서 = 후보 목록 순서)

1. **원래 증상(R3-0 리포 밖 상세 3절 항목표)**: 시험지 형식(keyword 로 가리킬 수 있는 일)으로 옮길 수 있는 것을 전부 넣는다.
   - done 9개 -> 끝난 항목 후보. 그중 세트 A 항목과 같은 일 6개(R3-0 겹침 표)는 세트 A 항목 바이트 복사(id 그대로), 겹치지 않는 3개는 새 id `S01`~.
   - partial 3개 -> `partial` 후보. 셋 다 세트 A 항목과 같은 일이라 바이트 복사(id 그대로).
   - open 19개 -> 대조군 후보. 세트 A·B 대조군과 같은 일 4개는 바이트 복사, 나머지 15개(키 있음 9, 없음 6)는 새 id `SC01`~.
   - unknown 11개 -> 넣지 않는다(허용 근거로 상태를 정할 수 없다).
   - 새 항목 keyword 는 R3-0 항목 이름·이슈 번호에서만 정한다(뱅크를 보기 전).
2. **키 있음 전수(닫힌 이슈)**: 소유자 리포 전부에서 `stateReason=COMPLETED`이고 `closedAt` < 2026-10-26T19:30Z(D10 스냅숏)인 이슈 전부(읽기 전용 `gh issue list` 조회, 2026-11-01 기준 약 237건), 1번에 든 이슈는 뺀다. 표본이 아니라 전수이고, 순서는 (리포, 번호) 정렬 뒤 `random.Random(341).shuffle`.
   keyword 는 세트 A 방식(이 리포 이슈 = 맨 번호 `#N` + project_hint, 다른 리포 = `<리포> #N` + project_hint = 리포 이름 소문자). 세트 A·B 항목과 같은 이슈면 그 항목 바이트 복사. 새 id 는 1번 다음 번호부터.
3. **키 없음 표본(완료 기록)**: 선정 사본에서 `memories/list`(읽기)로 원문 기억(world·experience, valid) 중 `kind:completion`(또는 `tag_aliases`가 그것으로 바꾸는 옛 kind) 태그가 있고 mentioned_at < 2026-10-28T15:00Z(날짜 없음 포함)이며 본문에 `#숫자`가 없는 것을 문서 단위로 모아(세트 B 방식), 문서 id 정렬 뒤 `random.Random(3411).shuffle` 순서로 훑는다.
   넣는 조건: 작업 하나의 완료 기록이다(조사·결정만·피드백·규칙·비업무 기록 제외, 세트 B 규칙), 앞 후보(1·2·3번)와 같은 일이 아니다, 그 기억 자신의 첫 문장에서 keyword(커밋 해시 또는 고유 작업 이름 4자 이상, 흔한 낱말 제외)를 뽑을 수 있다.
   project_hint 는 그 기억 본문·태그가 2번의 리포를 가리킬 때만 그 리포 이름, 아니면 없음(전체 페이지).
   **얼마나 훑나**: 전수(조건을 채운 문서 전부, 같은 순서, 훑은 문서마다 넣음·뺌 사유를 리포 밖 작업 파일에 남긴다). 키 있음 층이 닫힌 이슈 전수이므로 대칭이다.
   처음 규칙은 "근거 통과 수가 키 있음 층에 닿을 때까지, 최대 300개"였고 선정 run 뒤 최소 표본 미달로 측정 전에 바꿨다(1.6 `msg_6b2080baa55a`). 훑은 수와 소요 시간은 2절에 적는다.
4. **대조군 보충**: 1번 대조군 중 **1.3 의 선정 run 감도 필터(하나 이상 경로 open)를 통과한 것이 10개 미만이면**(처음 판은 "열림 근거 확인 뒤 10개 미만", 1.6 `msg_6b2080baa55a`로 변경) 소유자 리포에서 2026-10-28T15:00Z 에 열려 있던 이슈(만든 시각 < D10 스냅숏, 지금 열림이거나 기준 시각 뒤 종결, 1번 이슈 제외, 27건)를 `random.Random(3412).shuffle` 순서로 넣는다. keyword·project_hint 는 2번과 같은 방식, 세트 B 대조군과 같은 이슈면 바이트 복사.
   같은 근거·선정 run 규칙을 거쳐 감도 필터를 통과한 대조군이 10에 닿으면 그 뒤 보충 후보는 뺀다(`supplement-stop`). 27건을 다 써도 모자라면 있는 만큼.

### 1.3 근거 확인과 선정 run (D10 v1.1.0 사본 1개, 결과는 선정에만 쓴다)

- 근거(런 1 `evidence`와 같은 규칙, `evidence --controls`): 끝난 항목·partial 후보는 keyword 별 식별자 recall 에서 완료를 말하고 mentioned_at < 2026-10-28T15:00Z 인 기억이 있어야 한다(사본이라 날짜 없음도 근거). 대조군 후보는 같은 규칙에서 상태만 열림. 근거가 없으면 뺀다(`no-evidence`, `no-open-evidence`).
- 선정 run: 근거 확인 뒤 후보 전부를 `score --judge v2 --paths abcd`로 한 번(a 1회, b full 1회, c 1회, d 1회) 채점한다.
  후보를 늘리면(3번 전수, 4번 보충) 목록 경로 (a)(b)(d)는 늘어난 전체 후보로 같은 선정 사본에서 다시 재고 그 결과를 전체 후보에 일관되게 쓴다. (c)는 항목마다 질의라 새 후보만 잰다. 처음 선정 run 과 다시 잰 결과의 차이는 2절에 적는다.
- **끝난 항목 선정 = 선정 run 의 네 경로 중 하나 이상에서 v2 판정 open.** 원래 증상 끝난 항목은 이 조건 없이 넣는다(원래 증상과 시험지의 겹침).
- **대조군 선정 = 열림 근거 + 선정 run 의 네 경로 중 하나 이상에서 open**(원래 증상 대조군 포함). 합격 조건이 "대조군 전부 open"이라 기준선에서 어느 경로에도 안 나오는 대조군(런 2 BC01·BC03 꼴)은 처치가 결코 합격할 수 없게 만든다. partial 은 완료 근거만 본다.
- 그 뒤 1.1 의 1 : 1 할당. 이 단계는 `select` 명령(질의 0회, 결정적)이 한다: 입력 = 후보 정답표(`strata` = id -> 키 유무·출처), 후보 evidence, 선정 run summary 들. 출력 = 세트 C 정답표·고정 세트·키 표(0600, 이미 있으면 거부).

### 1.4 측정 run 과 기준선 양성

- D10 새 복원 사본 2개(각각 따로 up, 같은 v1.1.0, 처치 없음, `HC_ITEM_STATUS` 미설정)에서 세트 C 를 잰다: (a) 유효 run 3개(시도 상한 6), (b) full 1회, (c) 1회, (d) 1회. 이 두 복원이 세트 C 기준선 v1.1.0 이고 영분포 원표의 입력이다.
- **기준선 양성 = 끝난 항목 중 두 측정 복원 모두에서 open 인 것**((a)는 복원마다 유효 run 3개 다수결, 동률 open). 경로별과 네 경로 합집합으로 센다. 선정 run 판정은 여기에 쓰지 않는다(평균 회귀 방지).
- 대조군은 경로별 open 수를 원표에 그대로 낸다. 경로별 합격 판정에 쓸 대조군 분모(두 기준선 복원 모두 그 경로에서 open 인 대조군)는 사전 등록 2부에서 코디네이터가 고정한다.
- 목표: 기준선 양성 30 이상(네 경로 중 하나 이상), 대조군 10 이상. 1 : 1 할당 뒤 끝난 항목 20 미만 또는 감도 필터 통과 대조군 6 미만이면 측정 전에 묻는다.
  측정 뒤 기준선 양성 30 미만이나 대조군 10 미만이면 다시 묻지 않고 측정과 원표를 끝까지 내고 "스펙 #336 최소 표본 미달 -> 런 3 합격 판정은 판정 불가"를 적는다(`msg_6b2080baa55a`).

### 1.5 경로 (d) 질의

- R3-0 상세 7절 후보 3개 중 **2번**(열림 어휘 세 계열을 고르게 담은 문안). 이유: (d)는 recall 검색어로 쓰이고, 원래 증상의 기제는 검색어의 열림 어휘가 낡은 인계 기억을 끌어온 것이다(R3-0 4절 갈래 2). 1번은 원래 요청 문장에 가장 가깝지만 열림 어휘가 하나다.
- 질의 = 세트 C 정답표 `query_instruction` + 줄바꿈 + `list_query`(문안은 리포 밖 정답표에만), `query_timestamp=2026-10-28T14:59:59Z`, `max_tokens=4096`(MCP recall 기본). 게이트웨이 MCP `recall` 1회.
- 판정은 결과 집합 하나에 항목마다 (c) 최신 상태 규칙 v2(`judge_recall_v2`)를 그대로 쓴다. keyword 가 든 결과가 없으면 unknown + absent. LLM 이 목록을 만드는 변형은 넣지 않았다.
