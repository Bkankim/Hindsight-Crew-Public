## 1. 판정 규칙 원문 (스펙 #318 "결정됨"에서 그대로)

운영판 트래커 #318 본문(공개하지 않음)의 57~77행("arm 판정", "E1' 권고 규칙", "벤치 판정(데이터 효과)")을 바꾸지 않고 옮긴다.

> - **arm 판정**(plan-review 20261031-054631 O1(decision), 코디네이터 결정. #323의 판정 명령이 기계적으로 내고 #326이 그대로 옮긴다)
>   - **판정 값**(경로별): 세트 A∪B 합친 끝난 항목 open 수다(세트를 합쳐 동적 범위를 넓힌다. 세트 A 15건만으로는 런 1 흔들림 3과 기준선 1~3이 겹쳐 "개선"에 닿을 수 없다).
>     - (a): 측정 상태마다 유효 run 3개의 끝난 항목 open 평균. 유효 run을 못 채우면 그 상태의 (a)는 판정 불가.
>     - (b): 페이지 첫 생성 결과(full)의 끝난 항목 open. delta는 판정에 쓰지 않고 보고만 한다.
>     - (c): 1회 값(결정적).
>     - 처치 arm은 반복마다 값 하나(v1, v2)다. 기준선(A·C는 기준선 main, B는 기준선 v1.1.0)도 같은 방식으로 재고, (b)는 첫 생성 2회의 평균을 쓴다.
>   - **흔들림 폭 W**(경로별) = max(arm 두 반복 값의 차, 기준선 반복 차). 기준선 반복 차는 (a) 유효 run 3개의 최대 - 최소, (b) 두 생성 값의 차, (c) 0이다.
>     - (a)의 기준선 반복 차는 개별 run 범위라 평균끼리 비교보다 보수적이다. 의도한 보수성이다: (a)는 런 1에서 run마다 0~3을 오가 단독으로 효과를 주장하기 어렵다. 그래서 (a)는 주로 "나머지 경로가 나빠지지 않음" 조건에 쓰이고, 개선은 대개 (b)(c)가 함께 채울 때 나온다(재리뷰 20261031-060700 O5, 코디네이터 결정).
>   - **합격**: 세 경로 모두, 두 반복 모두에서 합친 세트의 끝난 항목 open 0, 대조군 전부 열림, invalid 0. (a)는 유효 run 3개 전부가 이 조건을 채운다.
>   - **개선**: 합격은 아니면서 다음을 모두 채운다.
>     - 세 경로 중 2개 이상에서 두 반복 값이 모두 "기준선 값 - W"보다 작다.
>     - 나머지 경로는 두 반복 모두 "기준선 값 + W"를 넘지 않는다.
>     - 대조군 열림 수가 경로마다 두 반복 모두 기준선보다 적지 않다(값은 판정 값과 같은 방식으로 낸다: (a) 유효 run 평균, 기준선 (b) 두 생성 평균).
>   - **효과 없음**: 그 밖의 경우.
>   - **판정 불가**: 반복이 1회뿐인 arm(상한·70% 규칙으로 줄었거나, 반복이 "중단"됐거나, #325의 무효화 유지 확인에서 무효가 됐을 때), 또는 판정 불가 경로가 2개 이상인 arm. 경로가 판정 불가인 경우는 그 경로에 invalid가 있거나, (a) 유효 run이 모자라거나, 비교할 기준선 값이 판정 불가일 때다. 판정 불가 경로가 1개면 그 arm은 합격일 수 없고, 개선은 남은 두 경로가 모두 "- W" 조건을 채울 때만이다. 판정 불가여도 값은 보고한다.
>     - 처치 arm에서 (a)가 대조군 0 run 때문에 유효 run 3개를 못 채워 판정 불가가 되면 그 arm은 개선이 될 수 없다(처치가 대조군을 닫았을 수 있다). 처치 상태의 대조군 0 run 수를 판정 명령 출력에 넣는다. 완료 반복이 0회인 arm은 "미측정"으로 보고한다(판정 불가와 같이 권고 대상 밖).
>   - **E1' 권고 규칙**: 권고 후보는 처치 arm A·B·C와 **"읽기 경로만"(기준선 main 대 기준선 v1.1.0)**이다. "읽기 경로만"은 기준선 main을 arm처럼, 기준선 v1.1.0을 그 기준선으로 놓고 위와 같은 개선 규칙으로 판정한다(두 기준선 모두 재통합 없이 같은 방식으로 잰 값. 반복 대신 기준선 main의 (a) 유효 run·(b) 2회 생성으로 W를 잡는다). 그 결과가 개선이면 "릴리스 업그레이드만(수정이 든 릴리스 태그를 기다려 운영 업그레이드, 설정 변경 없음)"이 후보가 된다. 합격 arm이 있으면 그중 운영 비용(재통합 길이·롤백 비용)이 가장 낮은 것을, 없으면 개선 후보 가운데 같은 기준으로 고른다("릴리스 업그레이드만"이 가장 싸다). 모두 없으면 "운영 변경 없음"과 다음 후보(키별 상태 문서, 런 2 결과를 본 뒤 설계)를 권고한다. 벤치(데이터 효과) 판정이 PASS가 아닌 arm(문턱 초과뿐 아니라 INVALID·미측정 포함)은 권고에서 빼고 사유를 적는다. 근거: 재리뷰 20261031-060700 O1(decision), Codex C3, 코디네이터 결정.
> - **벤치 판정(데이터 효과)**: 런 1 방식("동시 두 세트, 한 run", `bench/README.md` "1단계 arm 벤치" 절)과 문턱(속도 3.0%, 섞은 p95 6.0%, 토큰 허용 0, `artifacts/arch-v2/r1-a-baseline.md` 187-189행)을 그대로 쓴다.
>   - 비교쌍: s1 = D10, s2 = 그 반복의 arm 백업(`--expected-overrides <LINEAGE>`). 처치 arm(A·B·C) 반복마다 1 run을 돈다(두 반복의 차가 벤치의 재통합 사이 흔들림이다).
>   - 게이트웨이 팔 ref는 런 내내 `270242e`(런 1 고정 ref, 문턱을 잰 A/A와 같은 게이트웨이)로 고정한다. #320·#321 머지가 비교에 끼어들지 않게 하려는 것이다.
>   - 정확도 축은 쓰지 않는다(관찰을 바꾸는 arm에서 설계상 늘 changed). 결과가 바뀐 쿼리 비율은 보고만 한다.

### 6.2 키 없는 항목이 B·C로 안 풀린 크기

| 경로 | 기준선 v1.1.0 | B r1 / r2 | 기준선 main | A r1 / r2 | C r1 / r2 |
|---|---|---|---|---|---|
| (a) 키 없음(14) 평균 | 0.67 | 0.33 / 0.00 | 0.33 | 0.00 / 0.33 | 0.00 / 0.33 |

| (c) 키 있음(16) | 2 | 2 / 2 | 2 | 1 / 2 | 2 / 3 |

(값은 2절 `key:false`·`key:true` 범위 줄.)

- 키 없는 항목은 (a)(b)에서 이미 거의 열려 있지 않다. 남는 것은 (c)의 K08·K16·B16 셋이다(3.2절). K08은 A·B·C 모두 r1 open, r2 not-open으로 반복 사이에 바뀌었다(`r2-a-arm.md:336`, `r2-b-arm.md:139`·`206`, `r2-c-arm.md:137`·`200`). K16은 A·C 두 반복 모두 open이고 B 두 반복에서 닫혔다. B16은 A 두 반복에서 open이고 무효화가 있는 B·C 네 반복에서 모두 닫혔지만, 근거 기억 키가 0개라 무효화 대상 쌍과 겹치지 않아(`r2-b-arm.md:310`) 연결 경로는 확인되지 않았다. 그래서 이 시험지로는 "키 규율을 넓혀야 풀리는 키 없는 열림"의 크기를 (c) 0~3건으로만 말할 수 있고, 그 변화가 키 무효화 때문인지는 가를 수 없다.
- 키 있는 항목의 (c) open은 B·C에서도 2~3건이 남았다(K01·K05 등, 3.2절). 키가 있어도 무효화가 그 항목의 (c) 결정 기억에 닿지 않은 경우다(K05는 무효화 대상 쌍 밖, K01은 대상인데도 open, `r2-b-arm.md:314`·`318`).
- 키 유무 판정 입력은 출처 기준이다. #322는 세트 A K14·K15·K16(키 유무 표 false)의 근거 기억에 `extract_keys`를 돌리면 키가 2~5개 나온다고 적었다(`r2-b-arm.md:326-328`). "출처 기준 키 없음"과 "본문 기준 키 추출"은 다를 수 있다. 판정 입력(키 유무 표)은 바꾸지 않았다.

## 8. 한계

- **R3(기준선 혼합)**: "같은 이미지 + 설정 불변 + 전수 재통합" arm이 없다. A vs 기준선 main에는 범위 효과와 재통합 자체 효과(#6164 통합 포함)가 섞인다(스펙 #318). 운영 결정("업그레이드만" vs "업그레이드 + 범위")에는 A vs 기준선 main 비교로 충분하다는 것이 스펙의 전제다.
- **벤치는 데이터 효과만**: bench 복제본은 v1.1.0 이미지로만 뜨므로(`bench/replica.py` 574-577행, 스펙 #318) main이 만든 arm 백업의 데이터 효과만 쟀다. 전제(main 백업을 v1.1.0 복제본에 복원·verify)는 #319가 확인했다(`r2-t1-main-baseline.md:223-228`). 이미지 효과는 다음 릴리스 태그 재측정 때 잰다.
- **main 고정 빌드**: upstream 고정 sha `b801b694...`의 비릴리스 빌드이고, Dockerfile `apt-get upgrade` 때문에 다시 빌드하면 재현되지 않는다(스펙 #318). 운영 업그레이드는 릴리스 태그로만 하므로 A·C 결과는 같은 수정이 든 릴리스 태그에서 확인 재측정이 필요하다.
- **판정 규칙의 검출력**: 개선 조건은 각 반복 값이 "기준선 값 - W"보다 작아야 한다(`bench/arch_v2_regression.py:1359`). (a)의 W는 기준선 유효 run 범위 3이고 기준선 값이 1.67(v1.1.0)·2.00(main)이라 문턱이 음수다. 그래서 (a)는 어떤 처치에서도 개선 경로가 될 수 없고, 개선은 (b)(c) 둘 다에서 큰 폭이 나와야만 나온다(스펙 #318이 의도한 보수성, 1절 인용 "(a)는 주로 ... 나빠지지 않음 조건에 쓰이고"). "효과 없음"은 "효과가 없다는 증명"이 아니라 "이 측정기로 개선을 검출하지 못함"으로 읽는다.
- **(c) 판정 규칙**: keyword가 맞는 recall 결과 가운데 상태 단서가 있는 것 중 `mentioned_at`이 가장 늦은 결과 하나(원문·관찰 구분 없음)의 열림/끝남으로 정한다(`bench/arch_v2_regression.py:516-536`). 관찰 층을 바꾸는 처치(A·C·main 업그레이드)가 (c)를 거의 움직이지 못한 이유의 후보다(검증 안 함).
- **(c) W = 0**: 같은 사본에서는 결정적이라 기준선 반복 차를 0으로 정의했지만, 같은 D10 v1.1.0이라도 런 1 2/15 -> 런 2 4/15(세트 A)로 달랐다(`r2-t4-setb-baseline.md:154-155`). 원인은 미측정이고, 런 1 산출물에는 세트 A 정답표 sha256이 기록돼 있지 않아 정답표 동일성도 해시로는 대조할 수 없다(이번 값은 부록 A.1). (c) 1건 차이는 이 폭 안이다.
- **B 오탐 표본**: 대상 12건 전수 검사에서 오탐 1/12 = 8.3%(문턱 20% 이하, 다항목 인계 원문의 일부 이슈가 아직 열림, `r2-b-arm.md:57`·`66`).
- **세트 크기**: 합친 세트 끝난 30건·대조군 6건. 기준선 값이 (a) 1.67~2.00, (b) 2.50, (c) 5로 작아 개선 폭의 동적 범위가 좁다. 새 대조군 BC01~BC03은 기준선에서 한 번도 open이 아니었다(6.1절).
- **절차 부분 이행**: A 완료 두 반복과 C r1은 "drain 직전 상한 확인"을 첫 poll로 대신했다(`r2-a-arm.md:369`, `r2-c-arm.md:63`). 값이 상한과 멀어 결과 영향은 없다.
- **메모리 조건**: A·C 사본만 `mem_limit` 5g다(3g OOM 뒤, `r2-a-arm.md:39`). 채점 조건(이미지·D10·하네스)은 같다.
